# 个人 AI 工程总览卡

个人 AI 仪表盘中负责“工程项目进度与现场”的独立工程总览卡，当前承接旧“项目雷达”功能。

这次发布只包含工程总览卡，不包含仪表盘的其他输入、知识、日记或今日安排卡片。

## 这张卡展示什么

- 小库全局、仪表盘产品、卡片项目和平级工程的目录层级
- 当前选中对象的目标、职责、文件边界、路线入口和原始需求
- 工作树、分支、HEAD、未提交文件、合并状态、PR / Review / CI 登记
- “首轮构建”和“后续迭代”两个工作模式
- 每个对象的 Git 历史、跨卡提交和隔离冲突
- 首轮路线的真实 Markdown 入口、每个分区的原文、代码范围、Git 快照和验收证据
- 左侧固定阅读目录、滚动高亮，以及可折叠的 L1 产品树和平级工程

## One-shot 进度口径

页面只在对象已经登记路线图功能单元时计算：

`有验收证据的已完成功能单元 ÷ 已登记功能单元`

Commit 数、文档数量和聊天消息数量都不进入分母。没有清楚的分母时，页面显示“首轮进度不计算”。当前工程总览卡自身示例为 `3/4 · 75%`，最后一个单元仍等待用户验收；这不是整个仪表盘项目的完成百分比。

## 本地运行

```bash
npm install
npm run dev
```

然后打开终端提示的本地地址。生产构建和测试：

```bash
npm run build
npm test -- --run
```

## 当前数据边界

这是工程总览卡的静态现场快照。它不会假装已经连接 GitHub、Linear 或 CI；GitHub 当前只保存这张卡的发布快照，Linear 不在本页实时读取。页面中明确标出外部实时源尚未接入。后续如果接入真实仓库，应由本地 Git、GitHub、CI 和项目文档提供事实，页面只负责汇总展示。

## 低负担更新规则

普通问答、一次性 debug 和没有改变项目事实的微小修改，不自动创建快照、Issue、PR、Review、CI 或 Commit。只有长期需求/架构变化、首轮单元完成、分支或工作树变化、验收/阻塞、或需要新对话交接时，才刷新对应项目文档和总览快照。
